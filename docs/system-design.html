Marksheet & Transcript Viewer

System design and setup guide · Moving the app from Google Apps Script to its own server · October 2026

Staff type a Student ID and get that student's Marksheet and Transcript as PDFs. Today this runs inside Google Apps Script. The new version runs on our own server (AWS EC2) but stays connected to the same Google Sheet: it reads the marks from it, fills in its template sheets, and lets Google make the PDFs, just like the Apps Script does.

The big picture

1 · Read
One request reads all program data sheets. The result is reused for 30 seconds, so a search is fast.
2 · Write
The student's marks go into that program's Marksheet and Transcript sheets.
3 · Export
Google turns those two sheets into PDFs. The app sends them back to the browser.

What happens when someone searches

Each program has its own sheets

Every program is wired to its own data sheet and its own two templates. An AC2 (Old) student only ever fills the AC2 (Old) sheets; an AC2 (New) student only the AC2 (New) sheets.

Adding a new program

  1. In the Google Sheet, add the data sheet plus its Marksheet and Transcript sheets (copy the closest existing ones).
  2. Add one entry for it in engine.py (sheet names and which cells hold the ID, name, dates and marks). Same as adding it to Code.gs today.
  3. Update the server: run the setup script again (Part E). Template changes on their own need nothing: they are read live.

How it was checked

✓ Same results as Code.gs for every student. The original Code.gs and the new engine were run side by side on all 9,507 students in the workbook, across all 8 programs: 0 differences in marks, grades, averages or transcript choice.

✓ Same cells written. 960 marksheets and transcripts filled by both methods were compared cell by cell: identical.

✓ Full search tested against a stand-in for Google built from the real templates, one student per program: the right sheets were filled and exported.

Things to know

Turn off the old link after switching. The old Apps Script and the new server both write into the same template sheets. If both are used at the same moment, one student's PDF could pick up another's marks. Once the new address works, stop using the Apps Script link.

Anyone with the link can search. This is the same as today's setting (ANYONE_ANONYMOUS). If that is not wanted, a login can be added in front.

Keep the key file secret. The service account key gives access to the Google Sheet. Never email it or put it in GitHub.

Setup guide, step by step

About an hour, done once. You need: a Google account that owns or can share the spreadsheet, an AWS account that can create servers, and (optional) access to your domain's DNS settings.

Part ACreate the Google "robot" account (service account)

  1. Go to console.cloud.google.com and sign in. At the top, click the project picker → New project. Name it marksheet-app → Create. Make sure it is selected.
  2. Search the top bar for Google Sheets API → open it → Enable. Do the same for Google Drive API.
  3. Menu → IAM & Admin → Service Accounts → Create service account. Name: marksheet-app → Create and continue → skip the roles → Done.
  4. Click the new account → Keys tab → Add key → Create new key → JSON → Create. A .json file downloads. This is the key: keep it safe.
  5. Copy the account's email (looks like marksheet-app@marksheet-app.iam.gserviceaccount.com).
  6. Open the Web Host Google Sheet → Share → paste that email → set to Editor → untick "Notify" → Share.
  7. From the Sheet's web address, copy the spreadsheet ID: the long code between /d/ and /edit.
If Google says key creation is disabled, your organization blocks it. A Google Workspace admin must allow service account keys for this project (policy iam.disableServiceAccountKeyCreation).

Part BCreate the server on AWS

  1. Sign in at console.aws.amazon.com. Pick the region at the top right (e.g. Canada (Central)).
  2. Search EC2 → Launch instance. Name: marksheet.
  3. Image: Ubuntu Server 24.04 LTS. Instance type: t3.small.
  4. Key pair: Create new key pair → name marksheet → Create (a file downloads; keep it).
  5. Network settings: tick Allow SSH (choose My IP), Allow HTTPS, and Allow HTTP.
  6. Storage: 20 GB. → Launch instance.
  7. Give it a fixed address: left menu Elastic IPs → Allocate → select it → Actions → Associate → choose the marksheet instance. Note the IP address.
If AWS says you are not allowed to launch instances, your AWS user needs EC2 permissions. Ask whoever manages the AWS account.

Part CPut the code and the key on the server

  1. In EC2 → Instances, select marksheet → Connect → EC2 Instance Connect → Connect. A terminal opens in the browser.
  2. Download the code (the repo is private, so use a GitHub token: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained → read access to taha-grade-lookup). When asked, the username is your GitHub name and the password is the token: 
    git clone -b ec2-port https://github.com/data-nav/taha-grade-lookup.git
  3. Save the key: on your computer, open the downloaded .json key in a text editor and copy all of it. Then on the server: 
    sudo mkdir -p /opt/mt
sudo nano /opt/mt/service-account.json
    Paste (right-click → Paste), then press Ctrl+O, Enter, Ctrl+X.

Part DRun the setup script

cd taha-grade-lookup
sudo bash deploy/install.sh

It asks for the spreadsheet ID (Part A, step 7) and a domain name. If the domain isn't ready yet, leave it blank. It then installs everything, starts the app, and prints the address to open. Search a Student ID to check it works.

Using your own domain: at your domain provider, add an A record (e.g. marks) pointing to the Elastic IP. Wait a few minutes, then run the script again and enter the domain. It sets up HTTPS automatically.

Part ELater: updating the app

cd taha-grade-lookup && git pull
sudo bash deploy/install.sh

Your settings and key are kept. Changes to template sheets in Google need no update at all.

If something goes wrong

What you seeWhat to do
"The app did not start"Run sudo journalctl -u marksheet -n 50 and send the output.
Error mentioning permission / 403The Sheet isn't shared with the service account email as Editor (Part A, step 6).
Error mentioning an API not enabledEnable both Google Sheets API and Google Drive API (Part A, step 2).
"Sheet … was not found"A sheet was renamed in Google. Rename it back, or update its name in engine.py.
The page doesn't open at allCheck the EC2 security group allows HTTP (80) and HTTPS (443).
